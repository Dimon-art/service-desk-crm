# Сервис заявок (Service Desk CRM)

Учебный full-stack проект для обработки обращений в службу поддержки: REST API, панель менеджера и портал заявителя.

**Стек:** React + Vite + Tailwind CSS, Express.js, SQLite (`data.sqlite`).

---

## Жизненный цикл заявки (8 статусов)

```
new → assigned → in_progress ⇄ need_info → completed → awaiting_confirmation → confirmed → closed
```

| # | Статус | Кто меняет | Описание |
|---|--------|------------|----------|
| 1 | `new` | Система | Заявка создана |
| 2 | `assigned` | Менеджер | Назначен исполнитель |
| 3 | `in_progress` | Менеджер/исполнитель | Работа ведётся |
| 4 | `need_info` | Менеджер | Нужна информация от заявителя |
| 5 | `completed` | Менеджер | Работа завершена |
| 6 | `awaiting_confirmation` | Менеджер | Ожидается ответ заявителя |
| 7 | `confirmed` | **Заявитель** | Результат подтверждён |
| 8 | `closed` | Менеджер | Заявка в архиве |

Диаграмма: [`docs/request-lifecycle.svg`](docs/request-lifecycle.svg)

## Роли

Подробнее: [`docs/roles.md`](docs/roles.md)

| Роль | Доступ |
|------|--------|
| **Гость** | Создание заявки |
| **Заявитель** | Своя заявка по `accessToken`, подтверждение результата |
| **Исполнитель** | Через панель менеджера (поле `assignee`) |
| **Менеджер** | Активные заявки, архив, смена статусов, backup |

## API

| Метод | Endpoint | Доступ |
|-------|----------|--------|
| `GET` | `/api/requests` | Менеджер / фильтр по `accessToken` |
| `GET` | `/api/archived-requests` | **Только менеджер** |
| `POST` | `/api/requests` | Публичный |
| `GET` | `/api/requests/:id` | Менеджер или `?accessToken=` (включая архив) |
| `PUT` | `/api/requests/:id` | Менеджер (только активные) |
| `POST` | `/api/requests/:id/requester-response` | Заявитель (`accessToken`) |
| `GET` | `/api/requests/:id/status-history` | Чтение |
| `GET` | `/api/backup/export` | Менеджер |

**Авторизация менеджера:** заголовок `x-manager-token: manager` или `?token=manager` (cookie на 24 ч).

## Портал заявителя

После создания заявки выдаётся ссылка:

```
http://localhost:3000/?requestId={id}&accessToken={token}
```

На этой странице заявитель видит статус и может подтвердить или вернуть заявку в работу (шаг 7).

## Сценарии проверки

1. **Создание заявки** — форма «Создать заявку», валидация полей, ссылка отслеживания после успеха.
2. **Назначение** — открыть заявку, выбрать исполнителя, статус `Назначена`.
3. **Полный цикл менеджера** — пройти статусы до `Ожидает подтверждения`.
4. **Подтверждение заявителем** — открыть ссылку отслеживания, нажать «Да, проблема решена».
5. **Закрытие** — менеджер переводит в `Закрыта`, заявка уходит в `archived_requests`.
6. **Архив** — меню «Архив», просмотр закрытых заявок (только менеджер).
7. **Комментарий без смены статуса** — изменить только комментарий в карточке и сохранить.
8. **Персистентность** — перезапустить сервер, данные остаются в `data.sqlite`.

## База данных

Файл `data.sqlite` (JSON-структура):

- `requests` — активные заявки
- `archived_requests` — закрытые заявки
- `request_status_log` — история статусов
- `notifications` — имитация email-уведомлений
- `escalations` — задел на будущее

# Учебный проект: Сервис заявок для небольшой команды

Это простой, учебный web-проект «Сервис заявок», спроектированный для демонстрации полного цикла разработки: проектирования базы данных, создания REST API, верстки интерфейса и локального сохранения данных.

Проект разработан на **современном full-stack стеке**:
- **Frontend**: React (с Vite для сборки) + Tailwind CSS (для стилизации) + Lucide Icons.
- **Backend**: Express.js (Node.js) для обработки API-запросов и маршрутизации.
- **База данных**: Реальная реляционная СУБД SQLite (файл `data.sqlite` в корне).

## 📂 Структура файлов проекта

Ниже представлена структура созданного приложения:

```text
├── package.json               # Зависимости проекта и скрипты сборки/запуска
├── tsconfig.json              # Конфигурация компилятора TypeScript
├── vite.config.ts             # Конфигурация сборщика Vite
├── metadata.json              # Метаданные приложения AI Studio
├── index.html                 # Главная точка входа HTML, синхронизирована с метаданными
├── server.ts                  # Серверное приложение (Express.js) + СУБД SQLite
├── data.sqlite                # Файл базы данных SQLite (создается автоматически на старте)
└── src/
    ├── main.tsx               # Клиентская точка входа React
    ├── index.css              # Глобальные стили с директивами Tailwind CSS
    ├── types.ts               # Глобальные типы данных TypeScript (сущность заявки)
    └── components/            # Модульные представления интерфейса
        ├── HomeView.tsx       # Главная страница: дашборд со статистикой и сценариями
        ├── CreateRequestForm.tsx # Форма для создания новых заявок (с валидацией)
        ├── RequestList.tsx    # Панель менеджера: фильтруемый список заявок
        └── RequestDetails.tsx # Карточка заявки: управление статусами и комментарии
```

### Назначение ключевых файлов:
1. **`server.ts`**: Инициализирует базу данных, обеспечивает автоматическую миграцию старых плоских данных в реляционную структуру, предоставляет REST API для работы с заявками (`GET /api/requests`, `POST /api/requests`, `PUT /api/requests/:id`), а также историю изменения статусов (`GET /api/requests/:id/status-history`).
2. **`src/types.ts`**: Описывает TypeScript-интерфейс `SupportRequest` в точном соответствии с техническим заданием.
3. **`src/components/HomeView.tsx`**: Отображает дашборд с показателями по каждому статусу (Новая, В работе, Нужна инфо, Закрыта) и выводит список проверочных сценариев.
4. **`src/components/CreateRequestForm.tsx`**: Форма отправки обращения. Реализует валидацию заполнения полей и выводит понятные ошибки, если требования не соблюдены.
5. **`src/components/RequestList.tsx`**: Позволяет менеджеру искать заявки по тексту и фильтровать их по статусам в один клик.
6. **`src/components/RequestDetails.tsx`**: Форма редактирования обращения. Позволяет менеджеру легко переключать статусы (`new`, `in_progress`, `need_info`, `closed`) и мгновенно сохранять новые комментарии.

## 🗄️ Структура хранения данных

База данных хранится локально в файле `data.sqlite` в структурированном реляционном JSON-формате и содержит три основные таблицы (массива данных):

### 1. `requests` (Заявки)
Содержит основную информацию по обращениям пользователей:
- `id`: уникальный числовой идентификатор заявки;
- `requester_name`: имя сотрудника, отправившего обращение;
- `requester_email`: электронный адрес для связи;
- `title`: краткая тема обращения;
- `description`: подробное описание возникшей проблемы;
- `status`: текущее состояние заявки (`new` | `in_progress` | `need_info` | `closed`);
- `manager_comment`: текст ответа или сопроводительной заметки менеджера;
- `created_at`: дата и время создания заявки (ISO 8601);
- `updated_at`: дата и время последнего изменения (ISO 8601).

### 2. `request_status_log` (Журнал изменения статусов)
Фиксирует историю смены состояний по каждой заявке:
- `id`: уникальный числовой идентификатор записи;
- `request_id`: ссылка на идентификатор родительской заявки (`requests.id`);
- `status`: состояние, в которое перешла заявка (`new` | `in_progress` | `need_info` | `closed`);
- `note`: текстовое описание или системная заметка о событии;
- `created_at`: дата и время смены статуса (ISO 8601).

### 3. `escalations` (Таблица эскалаций - задел на будущее)
Зарезервированная таблица для планируемой функциональности эскалации сложных заявок:
- `id`: уникальный числовой идентификатор записи;
- `request_id`: ссылка на идентификатор заявки (`requests.id`);
- `type`: текстовое описание типа эскалации;
- `status`: строковый статус эскалации;
- `manager_note`: необязательное примечание менеджера;
- `created_at`: дата создания записи эскалации;
- `resolved_at`: дата закрытия эскалации (или `null`).

## 🚀 Команды установки и запуска

### 1. Установка зависимостей
Установите все необходимые Node.js библиотеки и СУБД SQLite:
```bash
npm install
```

### 2. Запуск в режиме разработки (Dev Mode)
Запустите сервер разработки, объединяющий Express Backend и Vite Frontend:
```bash
npm run dev
```
После запуска проект будет доступен по адресу: [http://localhost:3000](http://localhost:3000)

### 3. Сборка для продакшена (Production Build)
Соберите клиентскую часть и соберите TypeScript Backend в один оптимизированный файл:
```bash
npm run build
```

### 4. Запуск собранного приложения
Запустите готовый собранный проект:
```bash
npm run start
```

## 🔍 Проверочные сценарии для тестирования

Для полной проверки функционала MVP выполните следующие шаги:

1. **Создание заявки с валидными данными**:
   - Перейдите в раздел **«Создать заявку»**.
   - Заполните все поля (Ваше имя, корректный email, тему, описание).
   - Нажмите кнопку **«Отправить заявку»** и убедитесь в успешном результате (отобразится номер заявки).

2. **Проверка валидации (без email или некорректный email)**:
   - Попробуйте отправить форму без заполнения полей или с email, не содержащим символ `@`.
   - Проверьте, что приложение отображает понятные предупреждения под соответствующими полями и не отправляет данные на сервер.

3. **Просмотр новой заявки в списке менеджера**:
   - Перейдите в меню **«Список (Менеджер)»**.
   - Убедитесь, что только что созданная заявка находится на первом месте со статусом **«Новая»**.

4. **Изменение статуса обращения**:
   - Кликните по заявке в списке, чтобы открыть ее карточку.
   - Выберите новый статус (например, **«В работе»**).
   - Нажмите кнопку **«Сохранить изменения»**. Убедитесь, что статус обновился, и кнопка подсветилась зеленым цветом.

5. **Добавление комментария менеджера**:
   - Находясь в карточке заявки, напишите комментарий в текстовом поле справа.
   - Нажмите **«Сохранить изменения»**.
   - Вернитесь к списку и убедитесь, что у заявки появился индикатор *«Есть комментарий»*.

6. **Проверка персистентности (SQLite)**:
   - Полностью перезагрузите страницу в вашем веб-браузере (или перезапустите сервер разработки).
   - Перейдите в список заявок и убедитесь, что все созданные вами обращения, их измененные статусы и комментарии остались в прежнем виде, так как они надежно записаны в СУБД `data.sqlite`.
